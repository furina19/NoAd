# 🐟 无广告（NoAd）

> 一只帮你自动跳过手机广告的肥鱼～

---

## ✨ 功能

| 功能 | 说明 |
|------|------|
| 🎯 **自动跳过广告** | 检测并自动点击"跳过/关闭/Skip"等按钮 |
| 🚀 **开机自启** | 手机开机后自动在后台运行 |
| 👻 **默默无闻** | 前台通知最低优先级，几乎不打扰 |
| 📊 **拦截统计** | 记录拦截次数、显示每个应用的广告拦截数 |
| 🪶 **极轻量** | APK < 3MB，内存占用极低 |

## 🛠 技术原理

通过 Android **无障碍服务（AccessibilityService）**全树遍历所有可点击节点 → **评分制**判断跳过按钮 → 只点分数最高且最"像跳过按钮"的那个：

| 分数 | 触发条件 |
|------|----------|
| 💯 100 | 强关键词（"跳过广告"/"关闭广告"/"Skip ad"）精确匹配 |
| 💯 100 | 倒计时格式：`跳过 5s`、`1S \\| 跳过`、`5s 跳过`（数字在前/后都支持） |
| 🟢 95 | 文案中同时含跳过词和倒计时 |
| 🟢 85 | `×`/`✕` 关闭符号 + 小尺寸（信息流广告卡片） |
| 🟢 80 | `contentDescription="关闭"` + 小尺寸 + 广告上下文 |
| 🟡 70 | "跳过"/"Skip" + 位于屏幕左上/右上角 |
| ⛔ 0 | 广告标签、广告主体、长促销文案、尺寸超标 → **绝不点击** |

**安全护栏（防误点广告主体）：**
- 📏 尺寸硬约束：宽度 20~360dp、高度 18~160dp，广告大图/视频/卡片直接拦截
- 🏷 广告标签黑名单：文本为"广告/廣告/AD/赞助/推广"的节点绝不点击（点了会跳转落地页！）
- 📝 长文案拦截：超过 24 字的节点视为广告主体
- 🚫 系统包名黑名单：状态栏、设置、下载管理器、拨号等 30+ 系统应用完全不处理
- ⏱ 延迟重扫：事件后 0.7s / 1.8s / 3.2s 各补扫一次（视频广告跳过按钮延迟出现）

### v1.3.3（当前）—— 多广告页 + 误点修复

| 问题 | 原因 | 修复 |
|------|------|------|
| 一页多条广告只跳一个 | `scanAndClick` 只取 `sortedCandidates.first()`，其余候选全部丢弃 | 单次扫描改为遍历点击多个候选：中心点去重防止同按钮重复点，上限 3 个/次 |
| 运动/时间校园类 App 时灵时不灵 | `hasAdContext` 只搜 2 层祖先 + `AD_CONTEXT_WORDS` 词库太少 | 搜 3 层祖先；新增「第三方」「为您推荐」「猜你喜欢」「联盟」「穿山甲」等常见中文广告文案 |
| 误点合法 ×/关闭导致跳转 | 阈值 70 太低（角落 ×=75 分即点）+ `isBottomArea` 逻辑永真 bug | 阈值提高到 75；修复 `isBottomArea` 去掉永真条件 |

### v1.3.2 —— 弹窗/全屏广告关闭按钮补漏

| 问题 | 原因 | 修复 |

| 弹窗广告白底白 × 关不掉 | 卡片居中，× 不在屏幕边缘，旧逻辑不认 | 新增「卡片角落」判断：向上找 4 层祖先，若像对话框且按钮贴其顶部角 → 点 |
| 无文字描述的 × 图片按钮 | 无障碍读不到文字，无法定位 | 诊断日志新增 dump 无文字小可点击节点 |

### v1.3.1 —— 签名永久化修复

| 问题 | 原因 | 修复 |
|------|------|------|
| 装了新版还是签名冲突、无法覆盖 | GitHub Actions **每次构建都新生成一把临时密钥**，构建完就丢；本地构建又没有 keystore，只能回退默认 debug 签名 | 密钥改为仓库中持久保存的 `noad.keystore`：本地首次构建自动生成，CI 复用仓库里那份；两边签名完全一致 |

### v1.3.0 —— 真实广告点击失败的根因修复

| 问题 | 原因 | 修复 |
|------|------|------|
| 开屏广告「跳过 4」点了没用 | 跳过按钮的文字 TextView **本身不可点击**，点击事件绑在父容器上 | 向上找可点击父容器（最多 3 层），父容器尺寸合理就点它 |

| 卡片中部 × 不触发 | 旧逻辑只认屏幕顶部角落 | 新增「边缘关闭位置」：左右边缘 + 上 70% 区域也算 |
| 是否可点击的硬性限制 | 旧版直接跳过不可点击节点 | 改为：不可点击 → 找祖先 → 手势坐标 |

> ⚠️ **升级注意**：v1.3.0 新开了「手势点击」权限（`canPerformGestures`），
> 安装后必须去无障碍设置里**关闭「无广告」再重新开启**，新权限才会生效！

## 📱 获取 APK

### 🚀 方式一：GitHub Actions 自动构建（推荐！无需 Android Studio）

1. 把整个 `NoAd/` 文件夹推送到你的 GitHub 仓库
2. 推送后 GitHub Actions 自动开始编译（约 3 分钟）
3. 去仓库的 **Actions** 标签页 → 点最新的运行 → 底部 **Artifacts** 下载 `NoAd-APK`
4. 解压 zip → 得到 `app-debug.apk` → 传到手机安装 ✨

> 💡 也可以在 Actions 页面点 **「Run workflow」** 手动触发构建～

### 🛠 方式二：本地编译（需要 Android Studio）

用 Android Studio（Ladybug 或更新版）打开 `NoAd/` 目录：

```bash
# 在项目根目录执行
./gradlew assembleDebug
# APK 路径：app/build/outputs/apk/debug/app-debug.apk
```

## 🔑 关于覆盖安装（签名说明）

Android 系统要求：同一个 App 的新旧版本必须**签名相同**才能覆盖安装。

### 现在的机制（v1.3.1 起）

项目根目录的 **`noad.keystore`** 就是唯一签名密钥，**已被提交到仓库**：

| 场景 | 能覆盖？ | 原因 |
|------|----------|------|
| 本地编译（桌宠鱼 / Android Studio） | ✅ 可以 | 首次构建自动生成 `noad.keystore`，之后一直复用它 |
| GitHub Actions 下载 | ✅ 可以 | CI 复用仓库里的同一个 `noad.keystore`，只有缺失时才生成一次并提交回仓库 |
| 本地 ⇄ GitHub Actions 互相覆盖 | ✅ 可以 | 两边用的是**同一个密钥文件** |

> 💡 **首次构建会自动生成密钥**：`app/build.gradle.kts` 发现没有 `noad.keystore` 时，会用 JDK 的 `keytool` 自动生成，无需手动操作。
>
> ⚠️ **一次性成本**：之前几版用的是「每次构建都新生成、构建完就丢失」的临时密钥，那些 APK 的签名已经无法复现。所以从 v1.3.1 开始，**手机上的旧版需要先卸载一次**，之后所有来源的构建都能直接覆盖，再也不用手动卸载了。

> 🔐 密钥密码是固定的（`noad123`），仅用于这个个人小工具；如果你要上架应用商店或分发给他人，请换成自己的私有密钥。

## 🛠 诊断日志（排查漏跳广告）

如果遇到某个广告没有被跳过：

1. 打开「无广告」→ 拦截记录卡片右上角点 **「诊断日志」**
2. 点 **「开始记录」**
3. 去触发那个广告（等它完整出现几秒）
4. 回来点「诊断日志」查看内容

日志会记录：每次扫描的包名、找到的候选按钮（分数/尺寸/文字/是否可点击/是否用坐标点击），以及没找到候选时页面上所有含「跳/关/广告/×」文字的节点属性。

> ⚠️ 把这段日志发给肥肥，就能精确定位为什么没识别啦～

## 📱 安装后配置

### 1. 开启无障碍服务

安装后打开应用，点击 **「前往开启无障碍服务」**：
1. 系统设置 → 无障碍 → 已安装的应用
2. 找到「无广告」→ 开启

> ⚠️ **升级到 v1.3 后必须重开一次**：去无障碍设置里把「无广告」关掉再打开，让新的「手势点击」权限生效！

### 4. 启动后台服务

点击 **「启动后台服务」**，应用会在后台持续运行。

> 💡 **提示**：部分手机需要在「电池优化」中将「无广告」设为「不优化」，防止被系统杀死。

## ⚠️ 注意事项

1. **无障碍服务权限**：Android 系统要求用户手动在设置中开启，应用无法自动开启
2. **手机厂商限制**：部分国产 ROM（MIUI、ColorOS 等）可能限制无障碍服务自动启动，需要在「自启动管理」中允许
3. **兼容性**：理论上支持 Android 7.0+ (API 24+)
4. **不保证 100%**：部分应用使用自定义实现的广告跳过按钮，可能无法识别
